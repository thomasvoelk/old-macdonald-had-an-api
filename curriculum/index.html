🌱 Old MacDonald Had an API — Spring Curriculum

Fiona's alpacas live in your Java code. Now the rest of the farm wants to talk to them: a website, a phone app, a barn scanner. They all speak HTTP. In this curriculum you put a Spring Boot REST API around the domain you already wrote, test-first, and finally give it a real database.

This is the third sibling of Old MacDonald Had a Farm (Java/TDD) and The Data Barn (SQL). Same world, same Fiona. The Angular frontend is the next curriculum; there is none of it here.

What you will learn

  • Starting a Spring Boot application and letting Spring wire your objects together (dependency injection)
  • Exposing your domain over HTTP: GET, POST, PUT, DELETE, status codes, JSON
  • Keeping the business model and the JSON contract apart, with request and response records
  • Testing controllers with @WebMvcTest and MockMvc, test-first
  • Turning exceptions into proper error responses (400, 404, 409)
  • Validating input
  • Starting a feature from the inside or from the outside, and how mocks help when you start from the outside
  • Storing the farm in PostgreSQL with JdbcClient and plain SQL
  • Documenting your API with Swagger UI

Before you start

This curriculum starts after Java Lesson 19 (the end of Java Phase 4). Before Phase 2 you also need Java Lesson 21 (records) and Java Lesson 22 (Optional). Java Lessons 20, 23 and 24 can run in parallel or afterwards.

One-time checks live on their own page, not inside a lesson: Setting Up. Do that first.

How this curriculum works

Reading a lesson

Every lesson has the same shape as in the Java curriculum:

  • Story — what Fiona needs this time
  • 🌱 Spring Sprout — a short box explaining the Spring idea you need, with a link to the official docs. Spring concepts can't be discovered by trial and error, so you read first. Later steps explain new words again right where you use them
  • 🚜 Barn Briefing — a short box with background that is not Spring itself, for example how HTTP works
  • Your Task, Learning Goals, Getting Started
  • Test List — the behaviour to build, one test at a time; the acceptance criteria are hidden until you want them
  • Hints — three, escalating
  • When You're Done, Reflect, and a Copilot prompt for when you're stuck

The one rule

A controller never accepts or returns a domain object. The farm and the way it is shown on the web are different concerns.

We keep the code in separate places: the domain in alpacas, the web code in alpacas.web, later the SQL code in its own package. From Lesson 04 on, a controller has its own request and response types. You'll feel why in Lessons 03 and 04, and an architecture test will hold you to it later.

How we test

  • Domain code: plain JUnit, as before
  • Controllers: @WebMvcTest with MockMvc
  • One @SpringBootTest smoke test per phase: does the whole app start?
  • Mocks (Mockito) appear in exactly one lesson, on purpose

When you're stuck

  1. Re-read the Spring Sprout and the official docs link — is there an idea you skimmed past?
  2. Open Hint 1, then Hint 2, then Hint 3
  3. Still stuck? Use GitHub Copilot Chat with the prompt at the bottom of the lesson

Important: don't jump to the hints. Struggling productively is how you learn.

Phase-end demos

At the end of each phase, show your mentor:

  • Start the app and call the endpoints from the phase by hand
  • Run the tests and walk through one of them
  • Pick one design decision you're proud of and explain it in your own words
  • Answer the Reflect questions from the last lesson in the phase

Git conventions

Same as the Java course: one commit per green test.

PrefixWhen to use
feat:New behaviour, test now passes
test:A new failing test, or a test-only change
refactor:Structure changed, behaviour didn't
fix:Corrected a bug

A note on AI

GitHub Copilot is available to you, with one rule for this course: it never writes a controller, a test, or a SQL query for you. Each lesson ends with a Copilot prompt that keeps it Socratic. If you catch yourself pasting code you don't understand, stop and go back to the hints.

Check your setup, then begin with Lesson 01. 🌱
