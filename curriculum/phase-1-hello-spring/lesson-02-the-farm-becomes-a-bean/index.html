Lesson 02: The Farm Becomes a Bean

Story

The server is up, but it answers every question with "no idea". It has no farm. Until now, you wrote new Farm("Fiona's Farm") in your tests. In a web application, many requests arrive over time and they all must talk to the same farm. Someone has to create it once and hand it to whoever needs it. In Spring, that someone is Spring.

🌱 Spring Corner: beans and dependency injection

A bean is an object that Spring creates and manages for you. Spring keeps all beans in the application context (the container you started in Lesson 01). When one object needs another, it doesn't create it with new; it asks for it in its constructor and Spring passes it in. This is dependency injection: the object receives its dependencies instead of building them.

You know the idea already from the Java course: a Pen gets its Herd through the constructor instead of creating it. Spring just automates the "who builds it and who passes it in" part for the whole application.

There are two main ways to tell Spring about a bean:

  • put an annotation (like @RestController or @Component) on your own class. Spring finds it by component scanning
  • write a @Configuration class with a method annotated @Bean. The method builds the object and Spring keeps what it returns

Why does this lesson use the second way? Because Farm is a domain class, and domain classes never import Spring. You can't put @Component on it. A @Bean method in the web layer lets Spring manage a class that doesn't know Spring exists.

By default a bean is a singleton: one instance, shared. That is exactly what we want here: one farm. (It also means the farm is shared between requests, which we'll keep in mind in Phase 3 when requests start changing it.)

Official docs: Introduction to the Spring IoC container and beans, Using the @Bean annotation.

Your Task

Let Spring create one Farm named "Fiona's Farm" with two pens: Meadow (two alpacas: Dolly, 70 kg, 4 cm, white, and Pedro, 80 kg, 10 cm, brown) and Hilltop (empty). Put the code that builds it in a configuration class in alpacas.web.

This is sample data for now. Phase 4 replaces it with a database.

Learning Goals

  • Explain what a bean is and what the application context does
  • Define a bean with a @Configuration class and a @Bean method
  • Explain why a domain class is registered this way instead of by annotating it
  • Test that a bean exists, with @SpringBootTest and @Autowired

Getting Started

  1. Test first. In src/test/java/alpacas/web/ create a test class for your configuration. It is a @SpringBootTest that receives the farm with @Autowired (a field is fine in tests). It fails to start because there is no Farm bean.
  2. Make the first test pass with the smallest configuration class you can.
  3. Add the second test (the pens) and make it pass.
  4. Look at the fields you used with @Autowired in the test. In production code you will get your dependencies through the constructor instead. Lesson 03 does that.
  5. Commit after every green test.

Acceptance Criteria

Hints

Hint 1

You can't annotate Farm itself. So where can the knowledge "this is how a Farm is built" live, in code that is allowed to know Spring?

Hint 2

Create a class FarmConfig in alpacas.web and annotate it with @Configuration. Give it a method that builds and returns a Farm, annotated with @Bean. The method name becomes the bean's name. Both annotations are in org.springframework.context.annotation. The class and the method can be package-private.

Hint 3

The @Bean method looks like the code you wrote in the Java course: create a Herd, add two Alpacas, create a Farm, add a Pen holding that herd, add a second Pen with an empty herd, return the farm. In the test, a @SpringBootTest class (no arguments) with a field @Autowired Farm farm; is all you need.

When You're Done

Reflect

  • What would go wrong if every request did new Farm(...) itself?
  • What did you gain by not putting @Component on Farm? What would you lose if you did?
  • If two classes both ask for a Farm in their constructors, how many farms exist?
