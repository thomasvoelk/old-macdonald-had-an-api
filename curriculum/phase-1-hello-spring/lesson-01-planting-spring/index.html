Lesson 01: Planting Spring

Story

Your farm works. It is tested, tidy and correct, but it can only talk to a test class. Fiona, your customer, wants more: she wants to check her alpacas from the laptop at her desk, from the iPad in the barn and from her phone out in the pasture, without anyone starting a Java program. A frontend developer on your team will build those screens. "But every screen needs the same thing," says Fiona. "The farm has to answer the phone." The language all those devices speak is HTTP. Time to turn your Java project into a Spring Boot application.

🌱 Spring Sprout: what Spring Boot is

Spring Boot is like a meal kit. Instead of shopping for every ingredient yourself and hoping they go together, you order one box that already holds everything for the dish. You say "I want a web application", and Spring Boot brings a web server and the other pieces needed, already matched to each other. You order the box in your pom.xml. Today you do three things: order the box, write one small class that starts everything, and write a test that checks it starts. Each step below explains the new words right where you need them.

Spring Boot 4 renamed several things compared to older tutorials. If a search result looks different from this lesson, it is probably about an older version. Official docs: Spring Boot reference, system requirements.

Your Task

Make your project a Spring Boot application without breaking a single existing test, then start it.

  • Change your pom.xml: Spring Boot parent 4.1.2, java.version 25, two starters, and the Spring Boot Maven plugin (step 2 explains them)
  • Create the application class AlpacasApplication in your top package alpacas, next to the domain classes. step 6 explains why there
  • Write a smoke test: a test that only checks that the whole application starts
  • Start the application and look at it from outside

Learning Goals

  • Know what the parent, a starter and @SpringBootApplication each contribute
  • Add Spring to a project that already has green tests, and keep them green
  • Write and understand a @SpringBootTest smoke test
  • Start a server, call it, and read its answer

Getting Started

  1. Run mvn test first and note how many tests you have. That number must be the same at the end of this lesson, plus one.
  2. Order the box: edit pom.xml.

    First, the parent. It is the shopping list: it fixes the version of every library so that they all fit together. That is why most dependencies below have no <version>. You also set the Java version here.

    <parent>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-parent</artifactId>
    <version>4.1.2</version>
</parent>

<properties>
    <java.version>25</java.version>
</properties>

    Second, the dependencies. A starter is one dependency that pulls in a whole group of libraries. spring-boot-starter-webmvc means "everything for a web application". spring-boot-starter-webmvc-test is the same for tests and brings JUnit and AssertJ along. The Maven plugin lets you start the application with mvn spring-boot:run later.

    <dependencies>
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-webmvc</artifactId>
    </dependency>
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-webmvc-test</artifactId>
        <scope>test</scope>
    </dependency>
</dependencies>

<build>
    <plugins>
        <plugin>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-maven-plugin</artifactId>
        </plugin>
    </plugins>
</build>
  3. Your pom.xml already has JUnit and AssertJ entries from the Java course, and perhaps a maven-compiler-plugin or maven.compiler.* properties. The test starter already brings JUnit and AssertJ in versions that fit together, and the parent sets the compiler level from java.version. Remove your old versions of these and run mvn test again. All old tests should still pass.
  4. Commit: chore: turn project into a Spring Boot app.
  5. Test first: a smoke test.

    A smoke test is a test that does not check any behaviour. It only checks that the whole thing starts. The name comes from electronics: you switch a new device on, and if no smoke comes out, it passes the first check. For Spring you write it with the annotation @SpringBootTest, which starts your whole application for the test. It needs no assertion: if the application can't start, the test fails by itself.

    Now write it: in src/test/java/alpacas/, create a test class with @SpringBootTest and one empty test method. It fails, because there is no application to start yet.

  6. Write the application class.

    Spring Boot needs one class that starts everything: a class annotated with @SpringBootApplication and a main method that calls SpringApplication.run(...). That starts the web server and sets up your application. Spring looks for your other classes from the package of this class downwards, so it goes into your top package alpacas, next to your domain classes (Lesson 02 shows why that matters).

    The domain is what your application is all about: a farm, its pens and animals, which properties (attributes) an animal has, and the rules of the farm, such as when an alpaca is ready to shear. Farm, Pen, Herd and Alpaca are your domain classes. Rules change over time: imagine a new veterinary study says an alpaca is already too heavy at 85 kg, where your isHealthyWeight() allows more. You would change that one method, and nothing about web pages or databases would be involved. A good test: the domain would still make sense without any web page or database. Everything we add from now on only brings the domain to the outside world.

    Now write it: create AlpacasApplication in src/main/java/alpacas/ and make the test pass.

  7. Start it and look at it from outside. Run the application (IntelliJ's green arrow next to main, or mvn spring-boot:run). In a second terminal run curl -i http://localhost:8080/ (on Windows PowerShell, write curl.exe; the -i makes curl print the response's status line and headers). That is your first real HTTP request. Read what came back: the status line, the headers, the body. (A browser works too, but it hides the status line.) Stop the app with Ctrl+C.

📋 No Test List Today

A test list is for thinking through scenarios before you write a test: which cases, which edge cases, what could go wrong. Today there are no scenarios. It is technical setup, and the only test is a smoke test that says "the application starts". So there is nothing to brainstorm. From Lesson 02 on, the test list is back.

Hints

Hint 1

Look at step 5 again: one annotation starts your whole application for a test, and an empty test method is enough. It comes with spring-boot-starter-webmvc-test. Which one is it, and what does the test fail with while the application class doesn't exist yet?

Hint 2

The test annotation is @SpringBootTest (package org.springframework.boot.test.context). It searches upwards from the test's package for a class annotated with @SpringBootApplication. So put the test in alpacas, next to the application class.

Hint 3

The application class is tiny: a class annotated with @SpringBootApplication and a public static void main(String[] args) that calls SpringApplication.run(YourClass.class, args). Both come from org.springframework.boot (org.springframework.boot.autoconfigure.SpringBootApplication and org.springframework.boot.SpringApplication). Name it AlpacasApplication and put it in alpacas.

When You're Done

Reflect

  • Why do most dependencies in the pom.xml have no version number?
  • Your domain classes and the application class now share the package alpacas. Which kinds of code would you like to keep in separate packages below it later, and why?
  • The app answered even though you wrote no endpoint. What answered, and where did it come from?
