Lesson 01: Planting Spring

Story

Your farm works. It is tested, tidy and correct, but it can only talk to a test class. The neighbour's son has built a phone app that wants to ask Fiona's farm questions, and the only language the app speaks is HTTP. "First," says Fiona, "the farm needs to answer the phone." Time to turn your Java project into a Spring Boot application.

🌱 Spring Corner: what Spring Boot actually does for you

Spring Boot is a bundle of decisions. You say "I want a web application", and it brings a web server (Tomcat), a JSON library (Jackson) and sensible settings, all wired together. You get this through your pom.xml in three pieces:

  • the parent spring-boot-starter-parent fixes the versions of hundreds of libraries so that they fit together (that is why most dependencies below have no <version>)
  • a starter is a dependency that pulls in a whole group of libraries: spring-boot-starter-webmvc for "web application with Tomcat and JSON"
  • a test starter does the same for tests: spring-boot-starter-webmvc-test brings JUnit, AssertJ, Mockito and Spring's test tools

The entry point is one class annotated with @SpringBootApplication. Its main method calls SpringApplication.run(...), which starts the web server and creates the application context: a container that finds, creates and wires the objects ("beans") of your application. Lesson 02 is about beans.

The annotation also switches on component scanning: Spring looks for its own annotations in the package of that class and everything below it, and nowhere else. Remember that when you choose where the class goes.

This course uses Spring Boot 4.1. Boot 4 renamed several things compared to older tutorials (starter names, test packages, @MockBean is gone), so if a search result looks different from this course, it is probably about Boot 3. Official docs: Spring Boot reference, system requirements.

Your Task

Make your project a Spring Boot application without breaking a single existing test, then start it.

  • Change your pom.xml: Spring Boot parent 4.1.2, java.version 25, the two starters above, and the Spring Boot Maven plugin
  • Create the application class in a new package alpacas.web (the delivery mechanism lives there; the domain stays in alpacas)
  • Write a smoke test: a test that only checks that the whole application starts
  • Start the application and look at it from outside

Learning Goals

  • Know what the parent, a starter and @SpringBootApplication each contribute
  • Add Spring to a project that already has green tests, and keep them green
  • Write and understand a @SpringBootTest smoke test
  • Start a server, call it, and read its answer

Getting Started

  1. Run mvn test first and note how many tests you have. That number must be the same at the end of this lesson, plus one.
  2. Edit pom.xml. The parent and the Java version: 
    <parent>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-parent</artifactId>
    <version>4.1.2</version>
</parent>

<properties>
    <java.version>25</java.version>
</properties>
  3. The dependencies and the plugin: 
    <dependencies>
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-webmvc</artifactId>
    </dependency>
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-webmvc-test</artifactId>
        <scope>test</scope>
    </dependency>
</dependencies>

<build>
    <plugins>
        <plugin>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-maven-plugin</artifactId>
        </plugin>
    </plugins>
</build>
  4. Your pom.xml already has JUnit and AssertJ entries from the Java course, and perhaps a maven-compiler-plugin or maven.compiler.* properties. The test starter already brings JUnit and AssertJ in versions that fit together, and the parent sets the compiler level from java.version. Remove your old versions of these and run mvn test again. All old tests should still pass.
  5. Commit: chore: turn project into a Spring Boot app.
  6. Now test first. Write the smoke test in src/test/java/alpacas/web/. It fails because there is no application class yet.
  7. Create the application class in src/main/java/alpacas/web/ and make the test pass.
  8. Run the application (IntelliJ's green arrow next to main, or mvn spring-boot:run). Open http://localhost:8080/ in a browser, or run curl -i http://localhost:8080/ (on Windows PowerShell, write curl.exe). Read the status line and the body. Stop the app with Ctrl+C.

Acceptance Criteria

Hints

Hint 1

A smoke test says: "if the whole thing can start, nothing is badly broken". It needs no assertion. If the context can't start, the test fails by itself. Which annotation from spring-boot-starter-test starts an application context for a test?

Hint 2

The test annotation is @SpringBootTest (package org.springframework.boot.test.context). It searches upwards from the test's package for a class annotated with @SpringBootApplication. So the test and the application class should live in the same package, or the test in a package below it.

Hint 3

The application class is tiny: a class annotated with @SpringBootApplication and a public static void main(String[] args) that calls SpringApplication.run(YourClass.class, args). Both come from org.springframework.boot (org.springframework.boot.autoconfigure.SpringBootApplication and org.springframework.boot.SpringApplication). Name it AlpacasApplication and put it in alpacas.web.

When You're Done

Reflect

  • Why do most dependencies in the pom.xml have no version number?
  • What happens to a bean annotation placed in a package outside alpacas.web? Why did we choose that package for the application class?
  • The app answered even though you wrote no endpoint. What answered, and where did it come from?
