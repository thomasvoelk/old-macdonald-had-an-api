Lesson 01: Is the Farm Ready for the Web?

Phase 1 — Hello Spring. Style: Chicago (inside-out). We start from the domain you already have and build outwards. No Spring code in this lesson: we read first.

Story

The neighbour's son has built a phone app. It wants to ask Fiona's farm: "How many alpacas do you have? Which ones are ready to shear?" The app can't call your Java methods. It can only send HTTP requests and read what comes back.

Before you build anything, Fiona wants to know whether the farm you wrote is ready for that. Spoiler: it mostly isn't, and that is fine. It was written to be correct, not to be talked to over a network.

🌱 Spring Corner: what is a REST API?

A REST API is a program that waits for HTTP requests and answers with HTTP responses. A request has a method (GET = "give me", POST = "create", PUT = "change", DELETE = "remove"), a path (/pens/Meadow) and sometimes a body. A response has a status code (200 ok, 404 not found, 400 your request was bad, 409 conflict) and usually a body. The body is almost always JSON.

Java objects are not JSON, so something has to translate. Spring Boot does this with a library called Jackson. By default Jackson looks at your object and writes one JSON field for every public getter (getName() becomes "name", isHealthyWeight() becomes "healthyWeight") and for every public field. It calls those methods for real. Remember that; it matters in a minute.

Official docs: Spring Web MVC. You don't need to read it yet; Lesson 04 sends the first request.

Your Task

Audit your own domain for the web. Create a file docs/api-audit.md in your repo and fill it in. Nothing is compiled or run; the output is a document.

  1. Open Alpaca, Herd, Pen, Farm and Shepherd. For each class, write down everything that would feel awkward if a stranger's program talked to it over HTTP. Look at fields, return values, side effects and exceptions.
  2. Predict the JSON. Suppose a controller returned an Alpaca directly, e.g. Dolly (70 kg, 4 cm of fleece, white). Using the Spring Corner rule, write the JSON you expect, field by field. Note which fields you didn't mean to publish.
  3. Answer: what happens to the phone app if you later rename fleeceLength to fleeceLengthCm inside Alpaca?
  4. Sort your findings into two columns: "fix in the domain" and "keep the domain, protect the API from it".

Learning Goals

  • Read your own code as a stranger's client would see it
  • Understand that a JSON response is a public contract, while your classes are an internal model
  • Meet the project's core principle early: domain logic and delivery mechanism are separate concerns
  • Know why some problems are fixed in the domain and others are hidden behind a boundary

Getting Started

  1. Make a docs/ folder next to src/ and create api-audit.md.
  2. Work through one class at a time. For each public method ask: what does it return? Can it return null? Does it print? What does it throw?
  3. For each public field ask: who could change this from outside?
  4. Don't fix anything. You will fix some of these, test-first, in later lessons. Today you only find them.
  5. Commit with something like docs: audit domain for HTTP.

Hints

Hint 1

Imagine you are the phone app. You never see the Java code, only text coming back. Which of your methods would you be surprised by?

Hint 2

Jackson calls getters, including is...() methods, to build the JSON. Re-read the Spring Corner: which of your methods would be called? What happens inside them?

Hint 3

Look for three kinds of things: leaks (public fields, internals visible from outside), surprises (null, printing, unusual exceptions) and missing pieces (no ids). Then ask for each: is this wrong in the domain too, or is it only a problem once the domain is exposed?

When You're Done

Reflect

  • Who should decide what the JSON looks like: the people who write the domain, or the people who use the API? Can they be different people?
  • If the JSON shape and the Java class are the same thing, what is the cost of renaming a field?
  • Which of your findings would you fix even if the farm never went on the web?
