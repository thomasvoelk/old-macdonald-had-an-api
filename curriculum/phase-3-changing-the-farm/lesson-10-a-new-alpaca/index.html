Lesson 10: A New Alpaca

Story

A new arrival: Fiona has bought an alpaca called Triple H, 85.5 kg, 3 cm of black fleece, and she wants him in the empty pen, Cell. Ilona's form has four fields: name, weight, fleece length and fleece colour. "I send them all in one go," she says. "The pen is in the address, the alpaca is in the body."

This is the same kind of endpoint as in Lesson 09, with more data and more ways to go wrong. The new thing to learn is not a Spring annotation but how the answer's Location header has to be written.

🚜 Barn Briefing: spaces in addresses

An address on the web cannot contain a space. When a client wants the path /pens/Cell/alpacas/Triple H, it writes the space as %20: /pens/Cell/alpacas/Triple%20H. (It is called percent-encoding. Browsers, curl and your MockMvcTester do it for you.) When the request arrives, Spring undoes it before it gives you the @PathVariable, so inside your method the name is Triple H again. Until now this did not matter, because every name had one word.

But in a Location header you are the one who writes the address. Java's URI.create("/pens/Cell/alpacas/Triple H") refuses it and throws an exception. Spring has a helper that builds an address from a pattern and encodes the parts:

UriComponentsBuilder.fromPath("/pens/{penName}/alpacas/{alpacaName}")
        .buildAndExpand(penName, alpacaName)
        .encode()
        .toUri()

The braces here work like the ones in a controller pattern (Lesson 06): a placeholder, filled with the values you pass. .encode() turns the space into %20. More: percent-encoding on MDN and UriComponentsBuilder.

Your Task

Build POST /pens/{penName}/alpacas. The client sends:

{"name": "Triple H", "weight": 85.5, "fleeceLengthCm": 3, "fleeceColor": "BLACK"}
  • success: 201, header Location: /pens/Cell/alpacas/Triple%20H, body in the shape of AlpacaResponse (Lesson 06)
  • unknown pen: 404 (you will find that this needs no new code)
  • an alpaca with that name already in the pen (ignoring case): 409, with detail There is already an alpaca named Lita in pen Ring
  • a pen that already holds 30 alpacas: 409 (this needs no new code either)

Not yet: bad input. What happens with a fleece length of 11 or the colour PURPLE is an experiment at the end of this lesson. Lesson 11 fixes it.

Learning Goals

  • Combine @PathVariable and @RequestBody in one method
  • Map a request record to a domain object (and a text to an enum)
  • Build a Location header that survives spaces
  • See an earlier investment pay off: 404 and 409 come for free
  • Know which rule you can check in the controller and which belongs in the domain

Getting Started

  1. Start red. Write the test for the happy path in PenChangesTest with the body above (as a text block). Remember the habit from Lesson 09: the test creates its own pen first (Nursery, with a POST /pens) and posts into that, not into Cell. Assert 201 and a member of the body, then ask GET /pens/Nursery/alpacas and check that the list has one entry. Use Triple H from the start: the two-word name is the point of this lesson. The Location assertion comes in step 3, so you can watch it fail first.
  2. Request record and mapping. Create CreateAlpacaRequest(String name, double weight, int fleeceLengthCm, String fleeceColor). Look at the last component: the JSON carries the colour as text, because JSON has no enums; your domain wants a FleeceColor. Give the record a method toAlpaca() that does the mapping, like AlpacaResponse.from does in the other direction. Turning "BLACK" into FleeceColor.BLACK is a small job of its own: FleeceColor.valueOf(text) works, but it is case-sensitive. Put a tiny helper FleeceColors.parse(String) next to the record (package-private class in alpacas.web) that ignores case and throws an IllegalArgumentException with the message Unknown fleece color: PURPLE for anything else.
  3. The controller method. @PostMapping("/pens/{penName}/alpacas"), a @PathVariable for the pen and a @RequestBody for the request. Find the pen (farm.findPen), add the alpaca to its herd, return ResponseEntity.created(...) with an AlpacaResponse. First build the Location the naive way, URI.create("/pens/" + penName + "/alpacas/" + name), and add the Location assertion to your test. Run it: red, and the reason is the space. Then replace it with the UriComponentsBuilder from the Barn Briefing. Green.
  4. Look: two tests you do not have to make green. Write the test for an unknown pen (/pens/Nowhere/alpacas expects 404) and the test for a full pen (create a pen Crowd, post 30 alpacas into it in a loop with generated names such as "Extra " + i; the 31st expects 409). Both are green at once. Find out why: which lesson wrote the code, and where? Note it in docs/api-notes.md. (Your own pen Crowd is full afterwards, but no other test uses it.)
  5. The name is taken. Write the test: post Lita into Ring, expect 409 and a detail with the message above. Red. Check before you add: pen.getHerd().findByName(name) returns an Optional (Lesson 07), so isPresent() tells you. Throw a new web-level exception AlpacaAlreadyExistsException (the sibling of AlpacaNotFoundException, message as above) and map it in ApiExceptionHandler. Careful: the handler for IllegalStateException from Lesson 09 already answers 409; put both exception types into one @ExceptionHandler({...}) or write a second method, whichever reads better to you.
  6. Experiment (do not fix it yet). Start the application and send, with your docs/requests.http, a fleece length of 11, then the colour PURPLE, then a weight of -5. What status do you get for each, and what does the client see? Write it into docs/api-notes.md. The reference solution answers like this: 
    fleeceLengthCm 11      HTTP/1.1 500   (the domain throws IllegalArgumentException, nobody handles it)
fleeceColor PURPLE     HTTP/1.1 500   (same exception type, from your helper)
weight -5              HTTP/1.1 201   (nobody checks it, the alpaca simply exists)
    That is three different kinds of bad, and none is answered well. Lesson 11 sorts them out.

Acceptance Criteria

Hints

Hint 1

The happy-path test keeps failing on the Location header and you do not see why? Run it and read the exception: what does URI.create complain about? And for the duplicate: which method of Herd tells you whether a name is already there without throwing?

Hint 2

The request record maps itself: Alpaca toAlpaca() { return new Alpaca(name, weight, fleeceLengthCm, FleeceColors.parse(fleeceColor)); }. The helper loops over FleeceColor.values() and compares color.name().equalsIgnoreCase(text). A private static URI location(...) method in the controller keeps the builder out of the way.

Hint 3

The controller: Pen pen = farm.findPen(penName); if (pen.getHerd().findByName(request.name()).isPresent()) { throw new AlpacaAlreadyExistsException(request.name(), penName); } Alpaca alpaca = request.toAlpaca(); pen.getHerd().addAlpaca(alpaca); return ResponseEntity.created(location(pen.getName(), alpaca.getName())).body(AlpacaResponse.from(alpaca));. The advice: @ExceptionHandler({AlpacaAlreadyExistsException.class, IllegalStateException.class}) ProblemDetail conflict(RuntimeException e) { return ProblemDetail.forStatusAndDetail(HttpStatus.CONFLICT, e.getMessage()); }.

When You're Done

Reflect

  • The name rule is checked in the controller, because Herd.addAlpaca is used by many of your older tests that reuse names. Try putting the rule into Herd instead: how many of your existing tests turn red? What does that tell you about where a rule can go?
  • Two clients post "Lita" into Ring at exactly the same moment. Both checks say "not there yet". What would happen? (A database in Phase 4 will have an answer.)
  • Why does the response record call it fleeceLengthCm while the domain says fleeceLength, and the request record agrees with the response? What would Ilona say if the two differed?
