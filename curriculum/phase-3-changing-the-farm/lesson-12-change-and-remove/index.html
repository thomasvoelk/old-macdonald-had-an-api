Lesson 12: Change and Remove

Story

Two phone calls from Fiona. First: Triple H has been to the barber. He weighs 72.5 kg now and has no fleece left (0 cm), and his colour is listed as grey, because "black" was a typo from the start. Second: a buyer has collected Batista. He is gone, so take him off the list.

Ilona's screen has an edit form and a delete button per alpaca. "The edit form always shows all three values," she says, "so I just send all three back. And for delete I only need to know it worked."

🚜 Barn Briefing: replace and remove

PUT means: this is how the thing at this address should look now. The client sends the complete new version, and whatever was there before is gone. If it sends the same PUT twice, the second one changes nothing more. (The word for that is idempotent. You do not need it, but you will hear it.) Fields the client leaves out are not "kept as they were": they are missing, and so the request is incomplete and answers 400. Changing only one field is a different verb, PATCH, which this course does not build.

Two choices come with it. The name is the address of the alpaca (/pens/Cell/alpacas/Triple%20H), so the body does not carry it; the address says which alpaca is meant. And a PUT to an address where nothing lives could create the thing there, but here it answers 404: new alpacas are made with POST (Lesson 10), one way to do each job.

DELETE removes what is at the address. It answers 204, "done, nothing to send back", with an empty body. Deleting something that is already gone is 404.

🌱 Spring Sprout: put, delete and a fixed status

@PutMapping and @DeleteMapping work like @GetMapping and @PostMapping; only the HTTP method differs. A controller method that returns void answers 200 by default. When the status should always be the same, you do not need a ResponseEntity: put @ResponseStatus(HttpStatus.NO_CONTENT) on the method. Official docs: request mapping and @ResponseStatus.

Your Task

Build two endpoints.

PUT /pens/{penName}/alpacas/{alpacaName}, the client sends the complete new values (no name):

{"weight": 72.5, "fleeceLengthCm": 0, "fleeceColor": "GREY"}
  • success: 200, body in the shape of AlpacaResponse; the alpaca keeps its place in the herd
  • unknown pen or unknown alpaca: 404
  • a missing or invalid value: 400 (Lesson 11 should make this free)

DELETE /pens/{penName}/alpacas/{alpacaName}:

  • success: 204, empty body, and the alpaca is gone from the pen
  • unknown pen or unknown alpaca (also the second delete of the same one): 404

Learning Goals

  • Use @PutMapping, @DeleteMapping and @ResponseStatus
  • Take the identity of a thing from the address, not from the body
  • Build domain operations test-first before the web layer needs them
  • Recognise which tests you get for free from earlier lessons
  • Keep your tests away from Ring and Cell: create the alpaca in a pen of your own, then change it

Getting Started

  1. The domain first. Your Herd can add and find, but it cannot remove or swap. Write four tests in HerdTest before the controller exists: removeByName takes an alpaca out (the name matches ignoring case) and tells you with a boolean whether there was one; for an unknown name it returns false. replace(Alpaca) swaps the alpaca that has the same name for the new one, keeps its position in the list and returns true; with no such name it returns false and changes nothing. Red, green, one commit each. Why boolean? The controller will turn false into a 404, and the herd should not know anything about HTTP.
  2. Start red: PUT. In PenChangesTest create a pen Workshop (POST /pens) and post Triple H into it, exactly as in Lesson 10. Then mvc.put().uri("/pens/Workshop/alpacas/Triple H") with the body above. Expect 200 and a weight of 72.5 in the body, then check with GET that the colour is now GREY. Never replace Lita or Batista: other tests read them.
  3. The request record. Create UpdateAlpacaRequest(Double weight, Integer fleeceLengthCm, String fleeceColor) with the same validation annotations as CreateAlpacaRequest. The name is missing on purpose. Give it a method toAlpaca(String name): the name comes in as a parameter, from the address. (Why not make CreateAlpacaRequest do both jobs? Then a POST body could omit the name or a PUT body could contradict the address, and every endpoint would need rules for it. Two small records, each exactly as wide as its endpoint, are simpler.)
  4. The controller method. @PutMapping("/pens/{penName}/alpacas/{alpacaName}"), two @PathVariables and a @Valid @RequestBody. Find the herd, build the replacement, call herd.replace(...). If it returns false, throw AlpacaNotFoundException, which you wrote in Lesson 07 and which Lesson 08 already maps to 404. Otherwise return the AlpacaResponse. Green.
  5. Look: three tests you do not have to make green. Write the test for an unknown alpaca (PUT /pens/Ring/alpacas/Nobody, expect 404, it changes nothing in Ring because nobody is there). Then one for an unknown pen, and one with the field fleeceLengthCm missing (expect 400 and errors.fleeceLengthCm saying must not be null). The first is green because of step 4's exception; the other two are green at once. Which earlier lesson wrote each of them? Note it in docs/api-notes.md.
  6. DELETE. Write the test: pen Auction, post Triple H, mvc.delete().uri("/pens/Auction/alpacas/Triple H") expects 204; afterwards GET on the same address answers 404. Red. The method looks like the PUT without the body and returns void; annotate it with @ResponseStatus(HttpStatus.NO_CONTENT). When removeByName returns false, throw AlpacaNotFoundException again. Then add the test for an unknown alpaca (404).
  7. Experiments with the running app (use your docs/requests.http, against a pen you create first, say Workshop). Predict each answer, then look, and write the results into docs/api-notes.md:
    • A PUT to /pens/Workshop/alpacas/Triple H (after you posted him there) whose body also contains "name": "Other". What is the alpaca called afterwards?
    • A PUT with the address spelled triple h in lower case. What is the alpaca called afterwards?
    • The same DELETE twice. What does the second one answer?
    The reference solution answers like this: 
    "name": "Other" in the body      200, still called Triple H (the body's name is ignored)
address "triple h"               200, and the alpaca is now called "triple h"
DELETE a second time             404 "No alpaca named Triple H in pen Workshop"
    The first is what you wanted. The second is a small wart: replace finds the alpaca ignoring case, but then stores the new one under the spelling of the address. Decide in Reflect what you would do about it.

Acceptance Criteria

Hints

Hint 1

For replace you need the position of the old alpaca, so a loop with an index fits better than a for-each. List.set(index, alpaca) swaps without moving the others. For removeByName, look at what List.removeIf returns.

Hint 2

The mapping lives in the record: Alpaca toAlpaca(String name) { return new Alpaca(name, weight, fleeceLengthCm, FleeceColors.parse(fleeceColor)); }. The boxed Double and Integer unbox automatically here because @NotNull has already run.

Hint 3

The controller: Herd herd = farm.findPen(penName).getHerd(); Alpaca replacement = request.toAlpaca(alpacaName); if (!herd.replace(replacement)) { throw new AlpacaNotFoundException(alpacaName, penName); } return AlpacaResponse.from(replacement);. For the delete: @DeleteMapping("/pens/{penName}/alpacas/{alpacaName}") @ResponseStatus(HttpStatus.NO_CONTENT) void deleteAlpaca(...) and the same if (!...removeByName(alpacaName)) throw ....

When You're Done

Reflect

  • A client sends PUT to /pens/Ring/alpacas/Nobody. A friendlier API might create the alpaca instead. What would you gain, and what could go wrong (think of a typo in the name)?
  • You saw that a PUT to triple h renames the alpaca to triple h. Where would you fix it: in the controller, in Herd.replace, or not at all? Which one would you have to change tests for?
  • Is the second DELETE an error? Some APIs answer 204 again, so that "delete twice" looks the same as "delete once". What does 404 tell Ilona's screen that 204 would not?
  • Two clients edit the same alpaca at the same moment, one changes the weight, the other the colour, and both send all three values. What does the herd look like afterwards? (PATCH and, later, version numbers are what people use against this.)
