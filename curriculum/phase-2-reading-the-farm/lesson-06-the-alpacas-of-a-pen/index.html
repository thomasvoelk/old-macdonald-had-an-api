Lesson 06: The Alpacas of a Pen

Story

Ilona taps the row "Ring" on her overview and needs the animals in it: name, weight, fleece length and fleece colour. And Fiona has one more wish: "Every morning I want to know which alpacas are ready to shear, in the whole farm, without opening every pen."

🌱 Spring Sprout: path variables

You know the path from Lesson 03: the part of the address after the host and port. In http://localhost:8080/pens/Ring/alpacas it is /pens/Ring/alpacas. So far every path was fixed text. But there is one pen per name, and you do not want a separate method for every pen. So the controller describes the path as a pattern with a variable part in curly braces. The braces exist only in your code. The client never sends them: it sends a real path, and Spring fits the real path to the pattern.

In the controller (pattern):   @GetMapping("/pens/{penName}/alpacas")
In the request (real path):    GET /pens/Ring/alpacas
                                         ^^^^
                               penName = "Ring"

A request for /pens/Cell/alpacas fits the same pattern, with penName = "Cell". Spring hands that text to your method. Official docs: @PathVariable.

Your Task

Two endpoints, both returning an AlpacaResponse per alpaca:

  • GET /pens/{penName}/alpacas: the alpacas in that pen. GET /pens/Ring/alpacas answers [{"name":"Lita","weight":70.0,"fleeceLengthCm":4,"fleeceColor":"WHITE"}, …]
  • GET /alpacas/ready-to-shear: the alpacas in the whole farm that are ready to shear, as the same kind of entries

Look closely at the field name fleeceLengthCm: the domain calls it fleeceLength. The contract is allowed to differ from the model.

Learning Goals

  • Read a part of the URL with @PathVariable
  • Write a response record with a mapping method and reuse it in two endpoints
  • Decide field names for the JSON on purpose, independent of the domain names
  • Notice what happens when the pen does not exist (and why you will fix it later)

Getting Started

  1. Test first: the pen. Add a test to PenControllerTest: GET /pens/Ring/alpacas answers 200, the first entry has name Lita and fleeceLengthCm 4, the second has fleece colour BROWN. Fleece colour is a FleeceColor in the domain but a plain string in the JSON; a record can hold a string of fleeceColor.name().
  2. Response record with a mapping. Create AlpacaResponse in alpacas.web. Put the copying in a static AlpacaResponse from(Alpaca alpaca) method inside the record, so the controller can write .map(AlpacaResponse::from) (a method reference). Reading a domain object is fine in the web package; handing one out is not.
  3. Make it pass. The controller method is annotated @GetMapping("/pens/{penName}/alpacas") and has the parameter @PathVariable String penName, which means: "take the part of the path called penName and give it to me as a String". The name in the braces and the parameter name must match. farm.findPen(penName) gives you the pen and getHerd().getAlpacas() its alpacas. Commit.
  4. Names are case-insensitive because her findPen compares with equalsIgnoreCase. Write a test that /pens/ring/alpacas also works, so the behaviour is a decision and not an accident.
  5. Ready to shear. Test first: GET /alpacas/ready-to-shear answers 200 with exactly one entry, Batista (10 cm of fleece). farm.allAlpacasReadyToShear() does the work; the mapping is the same.
  6. Look at the console while the tests run. Your printlns in Alpaca are still speaking. Write down in docs/api-notes.md why they are not a problem for the JSON any more but still a problem.
  7. Break it on purpose. Start the application and open http://localhost:8080/pens/Nowhere/alpacas. Write down the status. Can Ilona's screen show anything useful to Fiona with that answer? Leave it for now. It is the subject of Lessons 07 and 08.

Acceptance Criteria

Hints

Hint 1

What is different between this path and /pens? The part that changes per request must be a placeholder in the path and a parameter in the method. Check the spelling: they must match.

Hint 2

The record needs four components. fleeceColor is the domain's enum; for the JSON you want its text. Where would you put code that translates one into the other: in the domain, in the controller, or in the record? Lesson 04 gives you a hint.

Hint 3

record AlpacaResponse(String name, double weight, int fleeceLengthCm, String fleeceColor) { static AlpacaResponse from(Alpaca a) { return new AlpacaResponse(a.getName(), a.getWeight(), a.getFleeceLength(), a.getFleeceColor().name()); } }. Controller: @GetMapping("/pens/{penName}/alpacas") List<AlpacaResponse> getAlpacasOfPen(@PathVariable String penName) { return farm.findPen(penName).getHerd().getAlpacas().stream().map(AlpacaResponse::from).toList(); }.

When You're Done

Reflect

  • A client asks for /pens/Ring/alpacas. What does Ilona's screen receive for a pen that does not exist, and what should it receive?
  • The response has no readyToShear field, although the domain has isReadyToShear(). If Ilona wants it, who decides: the domain, the record or Ilona?
  • The mapping lives inside the record. What would be the argument for putting it in a separate class? Against?
