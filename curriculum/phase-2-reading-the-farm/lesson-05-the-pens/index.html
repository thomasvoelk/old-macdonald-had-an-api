Lesson 05: The Pens

Story

The start screen works, and now Ilona wants the next one: the pen overview. "One row per pen," she says. "The pen's name and how many alpacas stand in it. Tap a row, and later I'll show the alpacas." Fiona nods: "Ring and Cell, at a glance."

Phase 2 is about reading. Every endpoint in this phase is a GET: it looks at the farm and changes nothing. Before you start, make sure you have finished Java Lesson 21 (records) and Java Lesson 22 (Optional); Lesson 05 already uses records, Lesson 07 uses Optional.

🚜 Barn Briefing: how Jackson writes JSON

Your controller returns a Java object, and the client receives text. The one who turns one into the other is not Spring itself but a library called Jackson. Spring calls it for you, and also sets the header Content-Type: application/json. You never import Jackson in this course, but you have already seen its work in Lessons 03 and 04. Its rules are small. We build them up one step at a time. Left is the Java, right is the JSON that Jackson writes:

1. A record with nothing in it is an empty JSON object, just curly braces.

record Nothing()
new Nothing()                   →   {}

2. A record with one component: one member, named like the component. Text has quotes.

record Greeting(String text)
new Greeting("hello")           →   {"text": "hello"}

From here on the record around it is left out. Each example adds one more component to a record like the one above, and shows the JSON member it becomes. The types are written with var to keep the lines short; the compiler works them out from the value (70.0 is a double, 70 would be an int).

3. Numbers (and true/false) have no quotes.

var kg = 70.0                   →   "kg": 70.0

4. A List becomes an array, in the same order.

var names = List.of("Lita", "Batista")
                                →   "names": ["Lita", "Batista"]

5. An enum is written as its name, in quotes.

var color = FleeceColor.WHITE   →   "color": "WHITE"

6. A null is written as null. The member is not left out. (Here var cannot work, because null has no type to guess.)

String nickname = null         →   "nickname": null

7. A record inside a record becomes an object inside the object.

var inner = new Greeting("hi")  →   "inner": {"text": "hi"}

8. A normal class, like your domain classes, has no components. Jackson looks at its getters instead. Here are four members of a class Barn:

public String getName() { return "Ring"; }   →   "name": "Ring"
public boolean isOpen() { return true; }     →   "open": true
public int countPens()  { return 2; }        →   (nothing)
private int secret = 3;                      →   (nothing)

Only getters count: a get... or is... method, with the name shortened. Two things follow that you have felt already: the names in the JSON come from the names in your Java (which is why the rename in Lesson 04 broke a test), and Jackson calls every getter, including the ones that print to the console. A response record with only the members you chose is the safer shape. Official docs: JSON in Spring Boot. (Phase 3 uses the same machinery in the other direction: JSON from a client becomes a record.)

Your Task

Build GET /pens. It answers 200 with a JSON array, one entry per pen, in the order the pens were added to the farm:

[{"name": "Ring", "alpacas": 2}, {"name": "Cell", "alpacas": 0}]

Remember the rule from Lesson 04: the controller returns a response record, never a Pen.

Learning Goals

  • Write a second controller and give it the farm through its constructor
  • Return a list of response records and read a JSON array in a test
  • Apply the model/contract separation from Lesson 04 without being told how
  • Choose a test for an empty case (a pen with no alpacas)

Getting Started

  1. Test first. Create PenControllerTest in alpacas.web. It looks like your FarmControllerTest, except that the annotation names the new controller: @WebMvcTest(PenController.class), with @Import(FarmConfig.class) as before. (If you write @WebMvcTest without a class, Spring loads every controller, which also works but gets slower with each new controller.) The new class does not exist yet. Let IntelliJ create it for you after the test is written.
  2. Read an array in a test. In a JSON array, $[0] is the first entry and $[1] the second (the briefing above said a list becomes an array in the same order), so .extractingPath("$[0].name") reads the name of the first pen. .extractingPath("$.length()") counts the entries.
  3. Make it pass. The smallest controller has a constructor taking the Farm, and one method annotated @GetMapping("/pens"). Inside, loop over farm.getPens() and build one record per pen. Use only methods that Pen already has. Commit after every green test.
  4. Start the application and open http://localhost:8080/pens in your browser. Your browser is just another client: it shows the array.
  5. Show the result to Ilona (your mentor plays Ilona): is this what her screen needs?

Acceptance Criteria

Hints

Hint 1

The test needs a name to read from the array. How does Jackson turn a Java list into JSON, and which path expression reaches the first entry?

Hint 2

You need one response record for a pen with a name and a count of alpacas. Which Pen method tells you the count? The mapping from Pen to your record is a stream with .map(...) or a plain loop. Both are fine.

Hint 3

record PenSummaryResponse(String name, int alpacas) {}. In the controller: return farm.getPens().stream().map(pen -> new PenSummaryResponse(pen.getName(), pen.totalAlpacas())).toList();. The test: assertThat(mvc.get().uri("/pens")).hasStatusOk().bodyJson().extractingPath("$[0].name").isEqualTo("Ring");.

When You're Done

Reflect

  • The list has the order of farm.getPens(). Is that a promise your API makes to Ilona, or an accident? How would you find out?
  • Ilona asks for a third field, capacity. Which files change?
  • Why is PenController a second class and not just another method in FarmController?
