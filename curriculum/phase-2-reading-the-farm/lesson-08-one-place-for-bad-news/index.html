Lesson 08: One Place for Bad News

Story

Hasi reviews your PenController: "That @ExceptionHandler in the controller only helps this one controller. And the unknown pen still ends in a 500. Every controller you write from now on will repeat it. Fix it once, for the whole application."

Ilona agrees, for her own reasons: "When something goes wrong, my screen should show the reason. Can the error always look the same, with a message I can display?"

🌱 Spring Sprout: central-error-handling

A class annotated with @RestControllerAdvice collects @ExceptionHandler methods for all controllers: one place that turns exceptions into answers. For the answer itself Spring has a class called ProblemDetail. Its objects describe an error in a standard format (RFC 9457) and are sent as application/problem+json, with the JSON members status, title and detail, so every error in your API looks alike. Official docs: Controller Advice and Error Responses.

Your Task

Create ApiExceptionHandler, a @RestControllerAdvice in alpacas.web, and move the handling there. Afterwards:

  • an unknown pen and an unknown alpaca both answer 404 with Content-Type: application/problem+json
  • the body carries the exception's message in detail, for example {"detail":"No alpaca named Nobody in pen Ring","status":404,"title":"Not Found","instance":"/pens/Ring/alpacas/Nobody"}
  • the handler inside PenController is gone

Learning Goals

  • Collect exception handling in one @RestControllerAdvice
  • Return a ProblemDetail so all errors have the same shape
  • Use a red test from the last lesson as the starting point
  • Know where an exception from the domain turns into an HTTP status

Getting Started

  1. Start red. The unknown-pen test from Lesson 07 is your first red. Add a second assertion to it and to the unknown-alpaca test: the content type is MediaType.APPLICATION_PROBLEM_JSON and $.detail contains the exception's message (The Pen you are looking for Nowhere does not exist, and No alpaca named Nobody in pen Ring).
  2. Create the advice. A class ApiExceptionHandler with @RestControllerAdvice and one method per exception type. A handler method may return a ProblemDetail; you build one with ProblemDetail.forStatusAndDetail(HttpStatus.NOT_FOUND, e.getMessage()). Spring Boot finds the class by itself, as it found your controllers: it lives in alpacas.web. In a @WebMvcTest the advice is part of the slice.
  3. One test at a time. Handle PenNotFoundException first (the red from Lesson 07 turns green), commit, then AlpacaNotFoundException; then delete the handler from PenController. The tests must stay green.
  4. See it with your own eyes. Start the application and call both errors with curl -i. Compare with the 500 body from Lesson 06 that you saw earlier.
  5. Where does the translation happen? PenNotFoundException comes from your domain, which knows nothing about HTTP. Only the advice knows it means 404. Write two sentences in docs/api-notes.md about why that is a good place, and what would be bad about putting @ResponseStatus on the domain exception.

Acceptance Criteria

Hints

Hint 1

Which class decides which exception means which status now? Is it a controller? Look for an annotation that applies to the whole application, not only to one class.

Hint 2

The advice has one method per exception type, with @ExceptionHandler(SomeException.class) and the exception as parameter. The body is a ProblemDetail; ProblemDetail.forStatusAndDetail(status, message) creates one.

Hint 3

@RestControllerAdvice class ApiExceptionHandler { @ExceptionHandler(PenNotFoundException.class) ProblemDetail penNotFound(PenNotFoundException e) { return ProblemDetail.forStatusAndDetail(HttpStatus.NOT_FOUND, e.getMessage()); } } and the same for AlpacaNotFoundException. In the test: .hasContentType(MediaType.APPLICATION_PROBLEM_JSON).bodyJson().extractingPath("$.detail").isEqualTo("…").

Reflect

  • Fiona wants a third kind of "not found" (a pen with that name exists, but not in this farm's region, say). How many files do you touch?
  • The message in detail comes straight from the exception. What if a message ever contains something the client should not see (a file path, an SQL error)?
  • Phase 2 only reads. What do you expect to be different about errors when a client sends data?
